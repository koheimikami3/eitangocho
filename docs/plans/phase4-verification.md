## C1: JSON エクスポート/インポート

- [x] 設定画面の「データ」セクションからエクスポートダイアログが開く
- [x] 保存先を選ぶとエクスポートが完了し SnackBar が出る
- [x] エクスポートした JSON をテキストエディタで開き、フォーマットが正しい
      (`version`, `exportedAt`, `words` 配列。`id` が含まれていないこと)
- [x] 単語を編集 → 編集前にエクスポートしておいた古いファイルをインポート
      → 上書きされず「変更なし」件数に計上される(updatedAt 規則の確認)
- [x] 単語を数件削除 → 削除前にエクスポートしたファイルをインポート
      → 削除した単語が「追加」件数として復活する
- [x] 内容の一部を書き換えた JSON(updatedAt を新しくした行を含む)をインポート
      → 該当行が「更新」件数に計上され内容が反映される
- [x] DB に存在するがインポート JSON には無い単語がある場合
      → マージ方式(追加専用)のため削除されず、そのまま DB に残る(想定通り)
- [x] インポート JSON 側で `word` 文字列自体を書き換えた場合(例: `rundown` → `rundow`)
      → マージキーが `word` 文字列(trim + lowercase)であるため別単語として
      扱われ、元の単語と新しい表記の単語が両方残る(リネームにはならない。想定通り)
- [x] 壊れた JSON(構文エラー)を読み込ませる → エラーダイアログが出る
- [x] `"version": 2` など未知バージョンの JSON を読み込ませる → エラーダイアログが出る
- [x] インポート/エクスポートのファイルダイアログでキャンセルしても何も起きない
- [x] 設定画面の表示サイズ(uiScale)を 2.0 にして小さいウィンドウでも
      「データ」セクションのボタンが溢れない
- [x] 「エクスポート...」「インポート...」ボタンの `...` 表記
      → 押下後に保存先/ファイル選択ダイアログが挟まる操作であることを示す
      HIG 準拠の表記(意図的)
