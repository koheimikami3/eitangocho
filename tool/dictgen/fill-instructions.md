# 事前生成辞書: 欠けた項目の補完と手直しの指示

英単語帳アプリの自動入力に使う辞書データを作る。入力は、アプリの今の取得経路
(EJDict・kaikki(Wiktionary)・Tatoeba)で引いた結果で、1 語ごとに日本語(`ja`)と
繁体字中国語(`zhHant`)の 2 言語ぶんがある。各項目を確かめ、欠けていれば埋め、
問題があれば直して、指定の JSON で出力する。

利用者は日本語・繁体字の話者で、英検 3 級〜準 1 級あたりの英語を学んでいる。
カードには見出し語・訳・英例文・例文の訳が並ぶ。

## 扱う項目

語ごとの品詞の欄と、言語ごとの次の 3 つ。IPA は扱わない(出力にも含めない)。

- `partsOfSpeech`: 品詞の配列。言語別には持たず語ごとに 1 欄で、名詞と動詞の両方の意味があれば両方入れる
  (入力では `ja` と `zhHant` に同じ値が入っている)
- `meaning`: 単語の訳
- `exampleEn`: 英例文
- `exampleTranslation`: 例文の訳

## 判断の基準

### 品詞(`partsOfSpeech`)

- 値は `noun` / `verb` / `adjective` / `adverb` / `other` の配列。前置詞・接続詞・代名詞・間投詞などは `other`
- **訳(日本語の `meaning`)に出てくる意味の品詞だけを付ける**。訳の先頭の意味の品詞を最初にする
  (例: `happy` は訳が「うれしい,幸せな / 満足した」なので `["adjective"]`。`give up` は `["verb"]`)
- 入力には Wiktionary の珍しい用法の品詞まで入っている(`happy` の noun・verb、`easy` の 5 品詞など)。
  訳に無い品詞は外す。句動詞は `verb`
- 空のときは埋める

共通の決まり:

- **よく使う意味から順に並べる**。学習者がまず覚えるべき意味を先頭にする
  (例: `issue` は「問題」、`present` は「贈り物」、`bank` は「銀行」が先頭)
- **主な意味が欠けていれば足す**(例: `present` の繁体字に「禮物」が無い、`light` の繁体字に「輕」が無い)。
  ただし、主な意味でない訳語を数を増やすためだけに足すことはしない
- **いちばん基本の訳語は外さない**。硬い語・帳簿や法律の用語に置き換えない
  (例: `borrow` の繁体字は「借」を残す。「借入」だけにしない。`lend` は「借 / 借給」)
- 古語・まれな意味・専門的すぎる意味・性的な俗語・差別語は外す。**易しい語でも同じ**で、
  学習者がその語で覚えない意味は入れない(例: `school` の「(魚の)群れ」、`house` の「議院」、
  `finish` の「表面處理」、`weather` の「風化する」、`buy` の「買収する」)
- 特に**訳の末尾**に、辞書にあるからと珍しい意味を足さない。末尾に足すか迷ったら入れない
  (例: `magazine` の「弾倉」、`cheek` の「尻の片側」、`tree` の「樹形図」、`module` の「宇宙船の区画」、
  `tournament` の「馬上試合」、`host` の「宿主」、`swim` の「目が回る」、`meal` の「粗びき粉」)
- 訳語は語にする。説明的な句にしない(例: `bank` の動詞は「把錢存入銀行」ではなく「存錢」)
- 日本語と繁体字で、先頭の意味をそろえる(例文は 1 つを共有するため)
- 空のときは埋める

日本語:

- **必要最低限の長さにする**。語義(` / ` 区切りの単位)は 1〜7 個。数は語の易しさではなく、
  学習者が覚えるべき主な意味の数で決める(主な意味が 6 つあれば 6 つ入れる)
- 1 つの語義の中は、訳語を 1〜3 個、`,` で区切る
- EJDict の表記の記号(`〈C〉`、`〈U〉`、`《+『of』+『名』》`、`《補語にのみ用いて》`、`『』`、読み仮名の `(もほう)` など)は落とす
- 意味の取り違えを防ぐのに要る短い補足だけは `( )` で残してよい(例: `(勾配が)ゆるやかな`、`(銀行の)口座`)
- 例: `issue` → `問題,問題点 / 発行 / (雑誌などの)号 / …を発行する,出す`

繁体字:

- 訳語を 1〜7 個、` / ` で区切る。数の決め方は日本語と同じ
- 簡体字が混じっていれば繁体字にする。台湾で一般的でない言い方は、台湾で一般的な言い方に替える
  (例: `可持續` → `永續`)

### 英例文(`exampleEn`)

- **日本語と繁体字で同じ英例文を 1 つ使う**(`ja` と `zhHant` の `exampleEn` は同じ文にする)
- 次をすべて満たす文にする。入力の例文(どちらかの言語)が満たしていれば、それを使ってよい
  - 8〜15 語(カードで 2 行に収まる長さ)
  - 見出し語(活用形でもよい)を、訳の先頭の意味で使っている。句動詞はひと続きで含む
  - 自然で、日常や学校・仕事の場面で使える文。固有名詞だらけの文、引用の断片、文法的に不完全な文ではない
- 短すぎるだけの場合も書き直す(例: `She looked happy.` は 3 語なので書き直す)
- **場面を散らす**。家庭・学校・職場・買い物・旅行・趣味・天気・健康・地域・交通など幅広く使い、
  同じ場面を続けない。図書館・台所・昼食・会議は使いすぎない。主語も I / we / she / they / my brother などを散らす

### 例文の訳(`exampleTranslation`)

- 英例文に対応した自然な訳。英例文を書き直したら、訳も新しく書く。英文に無い内容は足さない
- 英例文がそのままで訳が空、または訳が英文と合っていないときは、訳を書く
- **日本語の文体**: 基本は常体(例: 「彼女は家族と静かな夜を過ごして幸せを感じた。」)。
  依頼・勧誘・質問・案内・許可など、誰かに語りかける文や発言の文は、です・ます調にする
  (例: 「図書館の棚から好きな本を選べます。」「お部屋の番号を確認する間、こちらでお待ちください。」)
- 繁体字は台湾で自然な表現と繁体字で書く。読点などの約物は全角(`，`、`。`、`？`)にする

## 出どころ(`source`)

各項目に、次のどれかを付ける。

- `ejdict` / `kaikki` / `tatoeba`: その言語の入力の値をそのまま使った(入力の出どころをそのまま写す)
- `llm_filled`: 入力が空だったので埋めた
- `llm_revised`: その言語の入力の値を直した。並べ替えや削っただけでも、もう一方の言語の入力の例文を使った場合も `llm_revised` にする

直す前の値や直した理由は書かない(直す前の値は入力ファイルにあり、比べれば分かるため)。各項目は `value` と `source` だけにする。

例文の入力の出どころは `exampleSource`、訳の出どころは `meaningSource` にある。
例文の訳の出どころは、例文と同じ値を使う。品詞の入力は `ja.partsOfSpeech` で、出どころは常に `kaikki`。
入力と同じ配列(並びも同じ)のまま使ったときだけ `kaikki` とする。

## 出力

入力と同じ順で、全語を 1 つの JSON 配列として出力する。JSON 以外の文章は付けない。
キーの名前と入れ子は次のとおり。

```json
[
  {
    "word": "issue",
    "partsOfSpeech": {
      "value": ["noun", "verb"],
      "source": "kaikki"
    },
    "ja": {
      "meaning": { "value": "問題,問題点 / 発行 / (雑誌などの)号 / …を発行する,出す", "source": "llm_revised" },
      "exampleEn": { "value": "We need to talk about this issue before we decide.", "source": "llm_revised" },
      "exampleTranslation": { "value": "決める前に、この問題について話し合う必要がある。", "source": "llm_revised" }
    },
    "zhHant": {
      "meaning": { "value": "問題 / 議題 / 發行 / 期", "source": "llm_revised" },
      "exampleEn": { "value": "We need to talk about this issue before we decide.", "source": "llm_revised" },
      "exampleTranslation": { "value": "做決定之前，我們需要討論這個問題。", "source": "llm_revised" }
    }
  }
]
```
