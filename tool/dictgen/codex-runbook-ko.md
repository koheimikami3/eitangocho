# 事前生成辞書に韓国語を足す手順書(Codex 向け)

同梱の辞書にある語に、韓国語の訳を足す。収集 → 生成 → 検査を最後まで続けて行う。
作業ディレクトリは `tool/dictgen`(以下のパスはここからの相対パス)。

依頼文で出力先の名前(以下 `<出力>`。本番は `ko`、試作は `ko-trial`)を指定する。
出力先は `out/<出力>/`(50 語ごとの `input-001.json`, `input-002.json`, … と、それぞれの `output-NNN.json`)。

**途中で止まらない**: 何ファイルか終わった区切りで、報告や確認のために止まらない。途中経過の報告は要らない。
「4. 終わったら報告する」の条件がそろうまで、ユーザーの返事を待たずに続ける。

## 1. 収集(裏で走らせる)

依頼文で「収集済み」とあれば飛ばす。

```bash
python3 collect_ko.py out/<出力> > out/<出力>-collect.log 2>&1
```

- **通信が必要**(kaikki.org に問い合わせる)。通信を許可して実行する
- 1 語あたり約 1 秒かかる(1,000 語で約 20 分)。50 語ごとに `input-NNN.json` が 1 つずつできる。終わるのを待たず、
  裏で走らせたまま次の生成に進んでよい
- 途中で止まったり失敗したりしたら、同じコマンドをもう一度実行する。できているファイルは飛ばして続きから集める
- 辞書に語が増えたときも同じコマンドを回す。韓国語の入力がまだ無い語だけが、次の番号のファイルになる
- 進み具合は `out/<出力>-collect.log` で分かる。最後に `done:` の行が出たら終わり

## 2. 生成

`out/<出力>/` の `input-NNN.json` のうち、対応する `output-NNN.json` が無いものを番号の小さい順に処理する。

- 1 ファイルずつ、`fill-instructions-ko.md` の指示に従って処理し、結果を `out/<出力>/output-NNN.json` に書く
  (`input-007.json` なら `output-007.json`)。中身は指示の「出力」のとおり JSON の配列だけにする
- **訳と例文の訳は、自分で入力を読んで判断して書く**。プログラムやスクリプトで機械的に作らない
- 収集がまだ続いていて、処理できる input が無くなったら、少し待ってから次の input を探す

## 3. 検査

```bash
python3 validate.py --ko out/<出力>
```

- 形式と、機械的に確かめられる決まりを全ファイル分確かめる。「問題あり」のファイルは、
  出ている問題を直すように作り直す(同じ指示で `output-NNN.json` を書き直す)
- 1 ファイルにつき作り直しは 2 回まで。それでも残る問題は直さずに、最後の報告に含める
- 生成の途中で何度回してもよい(output の無い input は「未生成」として数えるだけ)

## 4. 終わったら報告する

収集のログに `done:` が出て(収集済みなら不要)、すべての input に output ができ、検査を最後に一度回したら終わり。
次を報告する。

- 合格・問題ありのファイル数と、残った問題の一覧(検査の出力をそのまま貼ってよい)
- 収集で失敗・やり直しがあったか
- かかった時間のおおよそ

## してはいけないこと

- `input-NNN.json`、`fill-instructions-ko.md`、`validate.py`、`collect_ko.py`、`build_bundle.py` を変えない
- `build_bundle.py` を回さない(アプリへの組み込みは、内容を確かめてから別に行う)
- git のコミット・プッシュをしない
